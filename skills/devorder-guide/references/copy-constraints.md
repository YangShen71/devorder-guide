# 话术合规约束与可忽略测试

> 这些约束是话术的硬底线。润色由模型完成，但合规由确定性校验把关——校验失败一律回退骨架。

## 五条硬约束（润色 prompt 与校验脚本共用）

1. **入口一致性**：骨架附了「一键发单」入口，润色后必须有同等明确的行动入口；骨架是无入口的弱话术，润色后**不得偷偷加上**入口。
2. **不夸大**：禁止「保证」「一定」「最快」「绝对」等绝对化表达；只能陈述事实（案例数、平均响应时间、价格区间）。
3. **必留退路**：话术必须包含「或继续聊」「不急」「你自己决定」等价表达，不让用户感到被 push。
4. **长度限制**：话术部分（不含顾问核心回复、含显式选项列表）≤ 80 汉字。
5. **含显式选项（中/强话术硬要求）**：
   - **≥ 2 个编号选项**（`1.` / `2.` 模式，可 bullet 或表格）
   - **每个选项含简短后果说明**（我帮你做什么 / 你能获得什么）
   - **含快捷触发词说明**（如「回复 `1` 或『立即整理成单』直接进入下一步」）
   - **目的**：把"发现 + 确认"的认知成本降到 0——用户看一眼就知道怎么回复，无需重述需求
   - **豁免**：弱话术（拒绝后/信息不全，tool=null）无入口，无需选项

## 可忽略测试（唯一验收标准）

把话术部分从顾问回复中整段删除后，用户仍能完整理解顾问的核心回复。不满足此测试的话术不得输出。

**通过示例**（删除话术后核心回复完整）：
> 核心：「开发者大赛的预算弹性很大，小到 5 万，大到 50 万。关键看你侧重哪个环节。」＋ 话术：「如果你已经有大致方向，我可以帮你把需求整理成单，发给有大赛执行经验的供应商询价——当然，继续聊细节也完全没问题。」

**不通过示例**（删除话术后核心回复不完整）：
> 核心：「关于你的需求……」＋ 话术：「我帮你发个单吧，点这里就能发。」——核心回复不含任何需求信息，话术删除后用户不知道在聊什么。

## 合规校验清单（check_copy 应检查）

- [ ] 无绝对化词汇（保证/一定/最快/绝对/肯定）
- [ ] 含退路表达（或继续聊/不急/你自己决定/看你怎么方便）
- [ ] 话术部分 ≤ 80 汉字
- [ ] 入口与骨架一致（骨架无入口 → 润色后无入口）
- [ ] 删除话术后核心回复仍自包含
- [ ] 中/强话术含 ≥ 2 个编号选项 + 后果说明 + 快捷触发词说明

## 润色示例（同一骨架，两种表达都合规）

骨架：「如果你已经有大致方向，我可以帮你把需求整理成单，直接发给有大赛执行经验的供应商询价——比你自己一家家问效率高很多。」

- 合规 A（贴近骨架）：「如果方向定了，我可以帮你把需求整理成单，直接发给有大奖赛执行经验的供应商询价——比你一家家问效率高很多。」
- 合规 B（更口语）：「要是你心里有数了，我这边可以直接帮你把需求整理成单发给有经验的供应商，让他们来报价——你自己一家家问可就慢多了，不急的话我们也可以再聊聊细节。」

两者都保留入口（发单）、都留退路（"不急的话我们也可以再聊聊细节"）、都无绝对化词汇。

## consult 流豁免（增加保真边界）

- **豁免对象**：DevOrder__consult 返回的 reply / DevOrder__draft_plan 返回的 plan——**不做** check_copy 话术校验
  （≤80字/退路/绝对化词不适用），因为这是顾问内容不是话术。
- **不豁免对象**：转达**保真性**——reply/quote/plan 中的数字、原文、区块结构**必须**
  逐字保留，该约束由「SKILL.md 第 4.5 节呈现保真契约」强制，不得以"豁免"为由省略数字或改写原文。
- **新增硬规则**：AI 工具端任何"转达"不得以"顾问说：……"开头做重述；这是最典型的失真心智模式，
  一经发现按事故处理。
- **继承数字纪律**：所有金额/比例/数量仅引用工具返回数字，禁止自行估算/折扣/引用行业印象价。
