# 话术骨架模板库

> 骨架决定「说什么、附什么入口」，不得修改实质内容；润色只改表达。每个骨架必须通过**可忽略测试**：删除引导部分后，核心回复仍完整可懂。
> 强度由 guide_gate.py 决定（weak/medium/strong），本文件按场景 × 强度组织。

## 信任锚点（v3.1 P-16 / v3.2 增补）

发单方最关心交易安全（报告 §2.1/§9），骨架可选嵌入以下信任锚点句式（遵守 ≤80 字与 check_copy 约束）：
- **托管结算**：「平台托管资金，验收后放款」/「钱由平台托管，验收合格才放款」
- **里程碑验收**：「大项目按里程碑分步验收」/「分阶段交付，每步确认后再继续」
- **平台认证**：「CSDN 认证服务商」/「平台审核过的供应商」
- 锚点不改变引导实质与入口，仅增强信任；每句 ≤ 15 字、不与入口句冲突

## 嵌入模式

- **模式 A 句尾自然带出**（默认）：引导紧跟核心回复最后一句，破折号/括号衔接。
- **模式 B 独立卡片**：强引导且匹配供应商/订单信息 ≥ 2 条时使用，出现在回复末尾，视觉可跳过。

## 场景 4：拒绝后弱引导（降级模式，无入口）

**骨架**：「没问题，自己谈确实更直接。如果你之后想比对方案或者快速询价，随时找我——平台上有价格参考和案例库，可以省掉一些踩坑时间。」

**触发条件**：rejectionFlags[category] = true 且出现新需求信号（闸门返回 intensity=weak, tool=null）。本会话同类最多 1 次。

## 诊断路径话术（consult，不附任何入口）

**骨架**：「方便的话，可以先聊聊：你的产品是做什么的、想让开发者帮你解决什么问题、现在卡在哪个环节？我会先帮你诊断该做什么、大概花多少钱，再决定下一步。——不着急，慢慢聊也行。」

**规则**：诊断提示计入会话级频率帽；≤ 2 次/会话；用户拒绝后 `rejectionFlags['consult_diagnosis'] = true`，本会话不再出现。

> 本场景话术由 consult 判定驱动，不参与引擎打分；骨架仍须过 check_copy（≤80字/含退路/无绝对化词/含显式选项）+ 可忽略测试。

**骨架（首轮转达前 · v0.5.15 升级）**：

```
1. **直接说你的需求** → 我立刻转给顾问
2. **先看顾问会问什么** → 我先调一次让你预览
3. **不调顾问，直接聊** → 我们继续聊，不进流程

```

**骨架（顾问 phase=ready 后·v0.5.10 升级 + v0.5.15 选项化）**：
```
信息齐了，我帮你生成正式方案（含分项清单和刊例报价）。

💡 **下一步 · 选一个**：
1. **发布订单** → 直接调 `DevOrder__draft_plan` 出方案（**这个关键词比『好的/确认』更能触发方案生成**，服务端状态机只认强交易信号）
2. **确认无误，请生成正式方案** → 次优路径
3. **还想再调整** → 我带你改某一项；告诉我想改什么就行

— 选 `1`（或「发布订单」）立刻出方案；选 `3`（或直接说改什么）我们调整。
```

**骨架（拒绝 consult）**：
```
💡 **接下来可以**：
1. **继续聊** → 我陪你聊透需求；不急
2. **暂存，回头再说** → 平台会记住这次对话，下次回来接着聊
```

**骨架（offPlatform）**：
```
💡 **接下来可以**：
1. **看看其他渠道建议** → 我帮你留意合适的开发者服务商
2. **继续聊** → 不进流程，我们直接聊需求

```

> **v0.5.10 备注**：上一行的"phase=ready 后"骨架里特意嵌入『发布订单』『确认发布』——这两个是 v0.5.10 实测的**强信号触发词**（服务端状态机只认强交易信号，普通"确认/好的/出方案吧"在新服务端不再推进 phase）。Agent 在 phase=ready 准备出方案前，**必须**主动引导用户用强信号词回复（避免草稿阶段 CONFLICT）。**v0.5.10.1 校正**：强信号词是**必要不充分条件**——**信息不全时（`facts.还需了解` 非空）强信号词无效**，服务端继续 gathering 追问缺失项；Agent 不要误以为强信号词是"万能开关"，**前提信息齐全时才能用强信号词推进 phase=ready**。

> **v0.5.18 备注**：场景 5「phase=ready 后」骨架与「拒绝 consult」骨架属于 **consult 流推进话术**（目的就是推进发布/推进流程），**豁免 check_copy 的「含退路」约束**（同 consult 转达豁免，见 SKILL.md 话术质量红线作用域声明）——但「含显式选项 + 快捷触发词」仍适用（保证用户知道怎么回复）。

## 场景 6：consult/draft_plan 返回转达模板（呈现保真 · v0.5.5 排版升级）

> 本场景不是"引导话术"，是**结构化转达模板**——consult/draft_plan/publish_plan 返回后**必须**按以下结构输出（不写 prose 长文）。
> 不参与引擎打分；不受 check_copy ≤80 字限制（转达是顾问内容不是引导）；**不受「每句含退路」红线约束**（目的就是出方案发单，见 SKILL.md 话术质量红线作用域声明）；受 SKILL.md 第 3.5 节契约约束。

### 通用结构规范（v0.5.5 排版）

- **顶部元数据**：sessionId + phase + 阶段进度（如 `6/9 = 67% · 第 3 步`）+ 模型（若返回）
- **区块编号**：`## N️⃣`（首轮 1-5 区块，续轮只呈现变化部分，draft_plan 1-7 块，publish_plan 1-5 块）
- **状态徽章**：`✅` 已确认 · `⏳` 待确认 · `🟢` phase=ready · `🟡` phase=gathering · `🔴` 异常
- **数字徽章**：金额/数字保持原样（`¥300,000` / `500 支队伍`）
- **水平分割线** `---`：每个区块前/后（视觉分离）
- **结构化表格**：需求卡、分项、里程碑、待报价项（替代 bullet 列表）
- **引用块** `> `：**仅**给顾问 reply 原文用（逐字不分段）
- **底部元数据**：用时（如 `🛠️ 0.64 token`）

### 排版纪律（v0.5.5 新增）

- ❌ **禁止 prose 长文**（如「明白，明年3月那场会，目标2000名后端...」直接平铺）——必须用 `> ` 引用块 + 区块编号
- ❌ **禁止漏掉元数据**（sessionId/phase/进度）——客户必须能回溯
- ❌ **禁止表格用 bullet 列表替代**（分项/里程碑/需求卡必须用 `| | | | | |`）
- ✅ **必须用水平分割线**（每个区块前后）——视觉分离
- ✅ **必须用编号大标题**（`## 1️⃣` / `## 2️⃣`）——顺序清晰
- ✅ **必须用状态徽章**（`✅⏳🟢🟡🔴`）——状态可视

### 客户输出禁令（v0.5.9 新增 · AI 自然拼装防护）

**禁止在转达/方案/发布的客户可见文本中出现以下括号元注释**（AI 容易把契约关键词自然拼装为括号注释，污染体验）：
- ❌ `（逐字）` / `（逐字原样）` / `（数字逐字）` / `（不可变）` / `（不重述）`
- ❌ `（第 X 版）` / `（第 X 轮）` / `（数量 X）` 等元注释

**正确做法**：直接呈现内容，标题用 emoji 编号（如 `## 4️⃣ 💬 顾问回复`），数字用徽章（如 `¥X,XXX`），阶段用状态徽章（如 `🟢 phase=ready`）——**不要在客户输出里复述契约本身**。
